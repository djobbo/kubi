# Vite+ toolchain (`vp` + pnpm from `.repos/vite-plus`)

**Goal:** Use [vite-plus](https://github.com/voidzero-dev/vite-plus) as the monorepo driver (`vp`) and **pnpm** as the package manager, with versions aligned to the vendored clone at `.repos/vite-plus`.

## Why

- Oxlint/Oxfmt, `vp run`, `vp check`, `vp staged`, and `vp config` match how this repo is already documented (`vp run setup` in AGENTS).
- `vp` downloads and pins **pnpm** from `package.json#packageManager` (same version as the vite-plus monorepo).
- Vendored `.repos/vite-plus` is the local source of truth for CLI behavior, RFCs, and template `vite.config.ts` patterns.

## Version pins (from vendored vite-plus)

Read from [`.repos/vite-plus/package.json`](../.repos/vite-plus/package.json) when refreshing:

| Field | Current vendored value |
|-------|------------------------|
| `packageManager` | `pnpm@10.33.2` |
| `vite-plus` (CLI) | `0.1.22` (`packages/cli`) |
| Node (engines) | `>=22.18.0` (vite-plus monorepo) |

Root [package.json](../package.json) must keep `packageManager` in sync after `syncVendoredRepos` updates vite-plus.

## Layout

```
kubi/
├── vite.config.ts          # defineConfig from vite-plus (run, staged, lint/fmt)
├── pnpm-workspace.yaml     # apps/*, packages/*, `catalog:` dependency versions
├── package.json            # `catalog:` deps only (versions in workspace yaml)
├── .repos/vite-plus/       # vendored upstream (gitignored)
└── pnpm-lock.yaml          # generated by vp install
```

## Commands (use `vp`; do not use Bun)

| Task | Command |
|------|---------|
| First-time bootstrap | `vp run setup` |
| Install deps | `vp install` |
| Dev (turbo) | `vp run dev` |
| Lint / format | `vp run lint` or `vp check --fix` |
| Typecheck | `vp run check:types` |
| Run script in workspace | `vp run -F @dair/api dev` |
| Run binary with local PATH | `vp exec drizzle-kit migrate` |
| Pre-commit (after `vp config`) | `vp staged` |

`vp` resolves **pnpm** from `packageManager`; you do not need a global pnpm install when using vp.

## Optional: link local `vite-plus` CLI

For dogfooding the vendored CLI instead of the registry tarball:

1. Build the clone once:

```bash
cd .repos/vite-plus
pnpm install
pnpm run build   # builds packages/cli dist + bindings
```

2. In root `package.json`, add:

```json
"pnpm": {
  "overrides": {
    "vite-plus": "link:.repos/vite-plus/packages/cli"
  }
}
```

3. `vp install` at repo root.

If the link is missing or dist is stale, fall back to `"vite-plus": "0.1.22"` in `devDependencies` (must match vendored `packages/cli` version).

## `vite.config.ts`

Root config uses `defineConfig` from `vite-plus` (see [monorepo template](../.repos/vite-plus/packages/cli/templates/monorepo/vite.config.ts)):

- `run.cache` — task caching for `vp run`
- `staged` — pre-commit via `vp staged` (replaces lint-staged config over time)
- `lint` / `fmt` — oxlint/oxfmt defaults from vite-plus

App-level Vite (TanStack Start) stays in [apps/client/vite.config.ts](../apps/client/vite.config.ts) using `vite` / `@voidzero-dev/vite-plus-core` as migrated.

## Runtime

| Layer | Tool |
|-------|------|
| Install, scripts, lint, hooks | **vp** + **pnpm** |
| API / workers / scripts | **Node.js** + **tsx** (`NodeHttpServer`, `dotenv/config`) |
| Setup | `vp exec tsx scripts/setup/setup.mts` |

See [.cursor/rules/node-toolchain.mdc](../.cursor/rules/node-toolchain.mdc). **Do not use Bun** anywhere in this repo.
